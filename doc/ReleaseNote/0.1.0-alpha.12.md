# EmPorium House 0.1.0-alpha.12

## Summary

The server now chooses its features from configuration. The engine's standard features (users, roles, robots,
business tasks) are always on; the container registry, CDN and NuGet server are switched with `modules` in
`emapi-config.json` or `EM_MODULE_<NAME>` environment variables. The desktop client follows the server and shows a
home card only for a feature that is on.

## New features

- Feature switches in the server configuration:

  ```json
  "modules": { "containerRegistry": true, "cdn": false, "nuget": false }
  ```

  `EM_MODULE_CONTAINERREGISTRY`, `EM_MODULE_CDN` and `EM_MODULE_NUGET` (`true` or `false`) override the file, so a
  feature can be switched from the `environment:` section of a Compose file.
- The desktop home screen hides the card of a feature the server does not run, and the card of a manager the
  signed-in account cannot open. No client setup is needed.

## Breaking changes

- **The CDN and the NuGet server are now off by default.** A server that uses them must turn them on explicitly
  (`"cdn": true`, `"nuget": true`, or `EM_MODULE_CDN=true`, `EM_MODULE_NUGET=true`); otherwise they answer 404
  after the upgrade. The container registry stays on by default.

## Upgrade notes

- Before pulling the new image, add the `modules` section to the server's config file, or the matching
  `EM_MODULE_*` variables to the container, for every feature that should stay on.
- Recreate the container after changing its environment (`docker compose up -d --force-recreate`); a restart keeps
  the old environment.
- Turning a feature off keeps its data under `/app/data` and in the database; turning it on again brings it back.
- The NuPak database scripts (`040-nupak.sql`, `vi_NuPak*`) are only required while the NuGet server is on.
- Older desktop clients keep working; they show a disabled feature as "Not enabled on this server" instead of
  hiding its card.
